网页版 PDF 密码移除工具 · 解密原理详解

本工具在浏览器本地完成 PDF 权限限制（Owner 密码）的移除，文件不上传服务器。

ⓘ
本文依据「不同 PDF 版本的加密方法对应关系」对照表，结合工具核心逻辑 unlock_core.js 的实现，逐层说明解密原理。

1PDF 加密体系概述

PDF 的安全机制由 标准安全处理器（Standard Security Handler） 实现。加密信息集中存放在文件内的 加密字典（Encryption Dictionary） 中，由 trailer 的 /Encrypt <对象号> 0 R 引用。

加密只影响两类内容：

  • 流（Stream）：页面内容、字体、图片等数据（/StmF 指定使用的密码过滤器）
  • 字符串（String）：书签标题、文档信息、URI 等（/StrF 指定）

解密需要解决两个问题：

  1. 文件密钥（File Key）：由用户密码（此处为空密码）+ 加密字典内容派生；
  2. 对象密钥（Object Key）：每个对象（按对象号 + 生成号）用文件密钥再派生一个独立密钥，用该密钥解密对应流/字符串，避免同一密钥直接加密全部内容。

2PDF 版本与加密方法对照表

下表为「PDF 版本 → 加密算法 → 密钥长度 → 加密字典字段」的对应关系：

  • /V（算法版本）决定密钥派生与加密算法族；/R（修订号）决定密码验证细节；

  • 「低安全性」= R5（密钥 = 一次 SHA-256）；「高安全性」= R6（密钥 = PBKDF2 式迭代哈希，抗暴力破解）。

4.1 解析加密字典

从 trailer 找到 /Encrypt <N> 0 R，按对象偏移读取加密字典文本，正则提取：

  • 算法族：/V、/R、/CFM（/V2 → RC4、/AESV2 → AES-128、/AESV3 → AES-256）
  • 密钥参数：/Length、/P、/O、/U、/UE（V5 时）
  • 字符串加密开关：/StrF（缺失或 /Identity 时字符串不加密）

/O、/U、/UE 同时支持 hex 字符串（<...>）与 括号字符串（(...)）两种形式，后者需做转义还原（\(、\)、\\、八进制 \ddd 等）。

4.2 文件密钥派生

V1–V4（经典加密，算法 2）

key = MD5( password(空) + O[0:32] + P(4字节小端) + ID[0] )
对 R≥3：重复 50 次：key = MD5(key + 前3字节)
取前 n 字节（n = Length/8；n 最大 16）

注意：AES-128（V4）且 /EncryptMetadata false 时，输入末尾再追加 4 字节 FF FF FF FF。ID[0] 来自 trailer 的 /ID，参与密钥派生，因此同一文件改字节会导致密钥变化。

V5（算法 2.B）

  • R5：key = SHA-256( password + U[32:40] + U[40:48] )（一次哈希，快但可暴力破解）
  • R6：迭代哈希，等效 PBKDF2 高强度：
hash = SHA-256( password + salt + udata )
count = 0
循环:
  count++
  k1 = password + hash + udata
  e  = AES-128-CBC 加密( 密钥=hash[0:16], IV=hash[16:32], 数据=k1 重复 64 次, 无padding )
  sel = (e[0]+...+e[15]) % 3        # 决定本轮用哪个哈希
  hash = SHA-256 / SHA-384 / SHA-512 ( e )
  当 count ≥ 64 且 e 末字节 ≤ count-32 时停止
key = hash[0:32]

R6 的停止条件与轮换哈希使得每次派生要做数千次 AES 块加密与哈希，这正是「高安全性」抗暴力破解的原理，也是解密耗时的主要来源之一。

4.3 密码验证（确定能否打开）

  • V1–V4（算法 6）：对空密码计算 MD5(空密码+padding+ID[0])，再按字节递增序号做 20 次 RC4 迭代，与 /U 比对。匹配即说明该文件可用空密码打开（本工具处理范围）。
  • V5（算法 11）：
    • 校验 U[0:32] == SHA-256( 空密码 + U[32:40] )；
    • tmpKey = SHA-256( 空密码 + U[40:48] )；
    • 文件密钥 = AES-256-CBC 解密(密钥=tmpKey, IV=全零, 密文=/UE, 无 padding)。

这一步同时完成了文件密钥的最终确认（实现中与 pypdf 交叉验证，R5/R6 文件密钥逐字节一致）。

4.4 对象密钥派生（算法 1 / 3）

每个对象按 对象号(3字节小端) + 生成号(2字节小端) 生成盐（salt）：

加密类型对象密钥
V=1（RC4-40，无 /CF）扩展密钥 = fileKey + salt（规范注 1：V=1 时 MD5 替换为 RC4，直接用扩展密钥作 RC4 密钥）；兼容生成器（pypdf 等）另按 MD5(fileKey+salt)[:n+5] 备选
V≥2 RC4MD5( fileKey[:n] + salt )[: min(n+5, 16)]
V=4 AES-128同上，salt 再追加 4 字节 sAlT
V=5 AES-256直接用 32 字节文件密钥（无 MD5、无对象盐，算法 3.1a）

RC4-40 文件的密钥选择是本工具近期修复的重点：同一派生错误会让所有流解密失败。实现采用「内容验证 + 主/备选密钥自适应」：先用规范密钥解密，若内容校验失败（解出的流不是合法 FlateDecode/图像数据）再试 MD5 备选密钥，并让字符串解密跟随流解密的统一结论。

4.5 流解密与内容验证

  • RC4：等长解密（plain = RC4(key, stream)）。因等长无校验，必须做内容验证：解出的字节必须是合法 FlateDecode 头（78 9C 等）或合法图像编码（JPX 需 FF 4F FF 51 头），否则视为未加密流，保留原样。
  • AES-128：CBC + PKCS#7 填充，使用浏览器 Web Crypto（crypto.subtle）。解密后长度缩短，必须按对象号降序解密并逐字节平移重建后续字节与 xref 偏移。
  • AES-256（V5）：对象密钥 = 文件密钥，AES-256-CBC + PKCS#7。流内嵌 16 字节随机 IV。

4.6 字符串解密

只有「经典加密（V<4）」或「加密字典显式 /StrF 非 /Identity」时字符串才加密（否则跳过，这正是某些文件书签完好的原因）。密文有两种形式：

  • 括号字符串 (...)：AES 时 IV + 密文 拼接，解密后重转义为安全括号字面量写回；RC4 时等长解密；
  • hex 字符串 <...>：同样按上述规则解密，写回为 hex。

解密结果必须保持字节长度与文本长度一致，并在替换后继续向后扫描（平移后的偏移自适应）。

4.7 输出重建

  • 移除 trailer 中的 /Encrypt 引用；
  • 保留并修正 xref 表/流（对象偏移已按解密长度变化平移）；
  • 传统 xref 表与 xref stream 两种结构均支持；
  • 重建后的 PDF 不再标记加密，可正常打开、编辑、打印、复制。

6适用范围与边界

支持

  • 空 user 密码、仅 Owner 权限限制（可打开但禁止编辑/打印/复制）的 PDF；
  • 全部五种加密方法：RC4-40、RC4-128、AES-128、AES-256（R5/R6）；
  • 传统 xref 表与 xref stream 两种结构。

不支持 / 明确拒绝

  • 需要打开密码（user password 非空）的 PDF——工具会提示先用密码打开；
  • 非标准安全处理器（第三方专有加密）的文件。

隐私 全部逻辑运行在浏览器本地 JavaScript，文件不离开本机，无需上传。

7验证方式

  • NIST 测试向量：纯 JS AES-128/256 块加解密与标准向量一致；
  • 文件密钥交叉验证：与 pypdf 派生的文件密钥逐字节比对（RC4/AES-128/R5/R6 全部一致）；
  • 端到端输出验证：解锁样例用 PyMuPDF 渲染，与原始未加密参考页逐像素一致；书签/元数据中文完整还原（括号与 hex 两种字符串形式均验证）；
  • 边界测试：带 user 密码的文件被正确拒绝。
